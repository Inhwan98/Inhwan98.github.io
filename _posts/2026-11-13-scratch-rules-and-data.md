## 한 일

- 긁기 손맛 시제품(S0)과 복권 전투 화면을 올렸습니다. 은박 마스크 · 가루 · 소리가 들어 있고, 전투 화면에서는 긁기와 전투 규칙이 함께 돌아갑니다.
- 화면 글자를 픽셀 폰트로 바꾸고 문자열을 5개 언어(한국어 · 영어 · 일본어 · 중국어 간체 · 번체) 표로 옮겼습니다.
- 복권 규칙을 바꿨습니다.
- 전투 데이터를 CSV 표로 옮기고 ID를 8자리로 통일했습니다.
- 구글 시트에서 표를 내려받는 에디터 도구를 만들었습니다.

## 바뀐 복권 규칙

- 복권 한 장은 **대표 그림 1칸 + 그림 6칸**입니다. 대표 그림과 같은 그림이 나오면 그 그림의 효과가 발동합니다. 대표 그림도 은박 아래에 있어 긁어야 보입니다.
- 당첨은 **확률**입니다. 전에는 모든 복권이 당첨이었는데, 이제 꽝이 있습니다. 꽝은 7칸을 다 긁었을 때 확정됩니다.
- 기본 캐릭터(단장)는 복권 없이 처음부터 전장에 섭니다. 전장에 아무도 없으면 그 복권은 반드시 용병이 당첨됩니다.

당첨 확률은 1,000판 시뮬레이션으로 정했습니다(균형 편성, 판단형 플레이어).

| 당첨 확률 | 전투 승률 |
| --- | --- |
| 40% | 41% |
| 50% | 56% |
| 60% | 70% |
| **70% (초안)** | **78%** |
| 80% | 84% |
| 100% | 92% |

## 데이터 표와 8자리 ID

- 용병 · 몬스터 · 효과 · 상품 · 복권 · 의뢰 · 웨이브를 CSV 표 7개로 옮겼습니다. 수치와 목록을 코드 밖에서 고칩니다.
- ID는 8자리 숫자입니다. 자리마다 뜻이 있습니다.

| 자리 | 이름 | 뜻 |
| --- | --- | --- |
| 1 | 대분류 | 무엇의 ID인가 (1 용병 · 2 몬스터 · 3 효과 · 4 복권 · 5 상품 · 6 의뢰) |
| 2~3 | 중분류 | 대분류 안의 갈래 |
| 4 | 등급 | 등급 · 희귀도 |
| 5~8 | 일련번호 | 같은 갈래 안에서 붙이는 번호 |

예: `20930001` = 2(몬스터) · 09(문지기) · 3(보스) · 0001.

- 표끼리는 ID로 가리킵니다. 첫 자리만 봐도 잘못된 종류를 가리켰는지 알 수 있고, 불러올 때 검사합니다(ID 자릿수와 중복, 가리키는 ID가 있는지, 숫자 범위, 웨이브 번호).
- 구글 시트는 내려받기 전용입니다. 시트에서 고치고 에디터에서 내려받으면, 검사를 통과했을 때만 CSV를 덮어씁니다. 원본은 저장소의 CSV입니다.
- 표는 어드레서블로 불러옵니다(주소 `Data/표 이름`). 처음에는 `Resources`로 읽었는데 같은 날 바꿨습니다. 표가 어드레서블에 등록돼 있는지는 검증 메뉴와 테스트로 검사합니다.
- 이전 모바일 경영 부분의 저장 데이터는 문자열 ID를 그대로 씁니다. 바꾸려면 저장 구조를 고쳐야 해서 손대지 않았습니다.

## 확인한 것

- Unity EditMode 테스트 전체 통과(어드레서블 전환 뒤 570건). 화면 없이 도는 규칙 테스트 98건 통과.
- 표 7개 37행 검사에서 문제 0. 문자열 표 120키 × 5개 언어 600칸에 빈칸 0.
- 표로 옮긴 뒤에도 1,000판 시뮬레이션의 균형 편성 승률은 78%로 같았습니다.
- 내려받기 처리는 대역 응답으로 확인했습니다. 같은 내용이면 변경 없음, 잘못된 ID면 중단하고 파일 유지, 로그인 페이지가 오면 안내, 바뀐 내용이면 갱신. 없는 시트 주소로 실제 요청하면 HTTP 404로 중단합니다.
- 전투 화면을 자동 입력으로 끝까지 진행해 결과 화면까지 콘솔 오류가 없었습니다.

위는 전부 테스트 · 시뮬레이션 · 자동 입력 검사입니다. 사람 플레이 검증이 아닙니다.

## 확인하지 못한 것

- 사람이 직접 긁어 본 손맛, 새 규칙의 재미, 60fps.
- 실제 구글 시트에서 내려받기(시트를 아직 만들지 않았습니다).
- 번역 품질(초안입니다), 1080p가 아닌 해상도, 플레이어 빌드.

## 남은 문제

- 균형 편성에서 판단형 플레이어 78%, 무작위 플레이어 77%로 승률이 거의 같습니다. 지금 규칙에서는 무엇을 고르는지가 결과를 거의 바꾸지 않습니다. 선택이 의미를 갖도록 규칙을 보완해야 합니다.
- 디버프가 나와도 "당첨"으로 셉니다. 꽝과 섞였을 때 어떻게 느껴지는지 확인이 필요합니다.
